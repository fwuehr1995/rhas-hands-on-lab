= Getting Started

== Overview

Here is a quick overview of the first activities in this lab:

- Register your own account on the Red Hat Automotive Suite.
- Launch a ready-to-code environment in Red Hat OpenShift Dev Spaces, created directly from the lab repository.
- Verify that the Cloud Automotive Image Builder service is reachable from your workspace.
- Authenticate to the Jumpstarter service so you can lease a test device later.

Behind the scenes, OpenShift Dev Spaces builds your workspace from the devfile in the lab repository and
provides all supporting infrastructure, so that you can focus on coding, not setup.

== Before you start

Some of the activities in this lab require you to perform certain actions in the various user interfaces or to type commands in a terminal window.
In order to highlight the different activities and their importance, we use the following conventions:

NOTE: This is information that you should know, but it is not critical for the success of this lab.

TIP: This is a tip that will help you complete the lab.

[#register]
== Register for the Red Hat Automotive Suite

There are no pre-provisioned accounts in this lab. You create your own.

IMPORTANT: Open the OpenShift console in a *private browser window*:

https://console-openshift-console.{openshift_cluster_ingress_domain}[window=_blank]

WARNING: Use a private window. If your browser already holds cookies for `opentlc.com` from another lab,
the console signs you in with those stale credentials instead of showing the registration page, and the rest
of this lab will fail in confusing ways.

IMPORTANT: On the login page, choose to *register* a new account.

image::starter/01-register.png[]

Fill in a username, a password and an email address.

NOTE: The email address is *not* verified. Any syntactically valid address works. Pick a username you will recognise again — it becomes your OpenShift identity and appears in the name of your build namespace.

TIP: Write your username and password down. Nothing else in the lab can recover them for you.

Once registered, you are signed in to the OpenShift console.


[#devspaces]
== Create your Dev Spaces workspace

Your development environment is created directly from the lab repository — there is no separate portal or catalog step.

IMPORTANT: Open Red Hat OpenShift Dev Spaces:

https://devspaces.{openshift_cluster_ingress_domain}[window=_blank]

IMPORTANT: Choose *Log in with OpenShift* and approve the permission request when prompted.

On the *Create Workspace* page, import the lab repository.

IMPORTANT: Paste the following into the *Git repo URL* field, then click *Create & Open*.

[source,sh,role=copypaste,subs="+attributes"]
----
{lab_repo_url}
----

image::starter/02-create-workspace.png[]

The workspace now starts. It walks through initializing, creating the workspace, waiting for it to start, and finally opening the IDE.

image::starter/03-workspace-starting.png[]

NOTE: This takes about a minute on the shared lab cluster. Masters and workers currently run on the same nodes; expect this to be quicker once worker nodes move to bare metal.

IMPORTANT: If prompted "Do you trust the authors of the files in this workspace?", click *Yes, I trust the authors*

TIP: On the bottom right of the screen you may see some popup notifications, you can safely dismiss them.

You should see a familiar *VS Code* development environment in your browser.


[#verify]
== Verify your environment

Before going further, confirm the workspace can reach the services it needs.

IMPORTANT: Select *Terminal -> New Terminal* from the menu at the top left, and confirm the prompt.

TIP: Enlarge the terminal panel so it fills the screen. You will spend most of this lab in it.

Your prompt reads `(venv) rhas-starter (main) $`. The Python virtual environment the lab needs is already active.

First, check that the Cloud Automotive Image Builder service is reachable:

[source,sh,role=execute]
----
caib status
----

You should see output like this:

[source,sh]
----
Server  https://ado-build-api-automotive-dev-operator-system.apps.rhas.sandbox3247.opentlc.com
Source  CAIB_SERVER env
Status  reachable
----

image::starter/04-caib-status.png[]

NOTE: `caib` reads the server address from the `CAIB_SERVER` environment variable, which is already set in your workspace. If the status is anything other than `reachable`, stop and ask for help — nothing later in the lab will work.

Next, confirm which OpenShift user you are:

[source,sh,role=execute]
----
oc whoami
----

This must print the username you registered with. Your workspace inherits the OpenShift login, so there is no separate `oc login` step.


[#jumpstarter]
== Authenticate to Jumpstarter

The `jmp` command-line tool needs its own authentication, using a browser-based device flow.

IMPORTANT: Run the login command. Note the hyphen — this is `jmp-login`, not `jmp login`.

[source,sh,role=execute]
----
jmp-login
----

The command prints a URL and waits:

[source,sh]
----
Fetching configuration from login.auto-jumpstarter.apps.rhas.sandbox3247.opentlc.com...
To sign in, open the following URL in your browser:

  https://keycloak-keycloak.apps.rhas.sandbox3247.opentlc.com/realms/openshift/device?user_code=XXXX-XXXX

Waiting for authentication...
----

IMPORTANT: Copy the URL with *Ctrl+Shift+C* and open it in a new browser tab.

TIP: In a terminal, plain Ctrl+C interrupts the running command instead of copying. Use Ctrl+Shift+C.

IMPORTANT: On the *Grant Access to jumpstarter-cli* page, click *Yes*.

image::starter/05-grant-jumpstarter.png[]

Back in the terminal, the command completes:

[source,sh]
----
Waiting for authentication...
Set 'she02' as the default client.
Server saved: https://ado-build-api-automotive-dev-operator-system.apps.rhas.sandbox3247.opentlc.com
----

image::starter/06-jmp-login.png[]

The name in the `Set '...' as the default client` line is your own username.
